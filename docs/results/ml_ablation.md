# Data-quality ablation: forecasts from corrupted data

Generated by `python -m healthbridge.ml ablation report`. The protocol was fixed in [../ml_decision.md](../ml_decision.md) before this was built. Corrupted copies of the raw snapshot were prepared three ways (clean through the pipeline, corrupted naively, corrupted through the pipeline) and forecasts were scored against the clean truth on forecasts present in all three. Degradation is the median paired difference in absolute percentage error relative to the clean variant, in percentage points (positive means worse than clean); the interval resamples countries.

Code version `aa05ea5`; clean snapshot `20261001T110703Z`; 9 corrupted snapshots (3 rates x 3 seeds). The pipeline-processed clean data drops 2.5% of values as flagged, so the reference already carries that cost.

## 6. Limits

- Injected faults are synthetic and the mixture is a choice; real errors may differ in kind and frequency.
- The naive variant is deliberately minimal. Variants (b) and (c) share most WHO values, so the comparison is mainly about validation, repair and cross-source checking.
- The pipeline variant also drops flagged values, including real events, a cost visible in the clean reference. Three corruption seeds per rate is a small number of corruption patterns.
- Results are pseudo out-of-sample on final-vintage modelled estimates (see ml_decision.md), and describe these four indicators only.
